**Не угадывать HTTP-пути и имена тулов.** Точки, где я не даю точную сигнатуру, помечены `[УТОЧНИТЬ]` —

Проверка перед каждым PR: `git diff --staged | grep -iE 'sk-|ALPACA_|ANTHROPIC_'` должен быть пуст.

**Qodo стоит с первого дня.** Ветка → PR → ревью → правки → merge человеком. Прямых пушей в main нет.

## 4. Компонент 1 — `mcp-guard`

Единственный путь агента к бирже. Сырые write-тулы Alpaca выключаются на уровне конфигурации агента
(раздел 6), поэтому обойти guard агент не может.

### Контракты тулов

Все тулы регистрируются с явными аннотациями. У FastMCP это параметр `annotations` при регистрации —
образец брать из `alpacahq/alpaca-mcp-server`, файл `src/alpaca_mcp_server/overrides.py`, там три готовых
примера.

```
get_mandate() -> Mandate
  annotations: readOnlyHint=True
  Текущий мандат с рассчитанными запасами по каждому лимиту.

check_order(symbol, side, qty, order_type, limit_price) -> CheckResult
  annotations: readOnlyHint=True
  Сухая проверка. Ничего не отправляет. Возвращает:
    { allowed: bool,
      breaches: [ { rule, limit, projected, headroom } ],
      portfolio_before: {...},
      portfolio_after: {...} }
  Это то, из чего пульт рисует карточку решения. Числа считаются здесь, не в модели.

submit_order_under_mandate(symbol, side, qty, order_type, limit_price, rationale) -> OrderResult
  annotations: readOnlyHint=False, destructiveHint=True, idempotentHint=False
  Прогоняет check_order повторно на актуальном состоянии. Если allowed=false — НЕ отправляет,
  возвращает отказ со списком нарушенных пунктов. Если allowed=true — отправляет в Alpaca.
  rationale обязателен и пишется в вахтенный журнал.

cancel_order(order_id) -> OrderResult
  annotations: readOnlyHint=False, destructiveHint=True

close_position(symbol, qty) -> OrderResult
  annotations: readOnlyHint=False, destructiveHint=True

get_session_state() -> SessionState
  annotations: readOnlyHint=True
  Ордера за день, позиции, реализованный и нереализованный P&L, что запарковано.

park(reason, intended_action) -> None
  annotations: readOnlyHint=False, destructiveHint=False
  Агент фиксирует, что хотел сделать и почему не смог. Попадает в журнал.
  Это не заглушка: список запаркованного — часть продукта.
```

**`submit_order_under_mandate` перепроверяет лимиты сам, а не доверяет предыдущему `check_order`.**
Между проверкой и отправкой проходит время, за которое состояние портфеля меняется.

### Проверки в `checks.py`

Чистые функции, без сети, покрытые тестами. Каждая возвращает `None` либо описание нарушения.

```
check_universe            символ входит в mandate.universe
check_instrument          тип инструмента разрешён
check_order_type          тип ордера разрешён
check_position_limit      позиция после сделки ≤ max_position_pct от капитала
check_gross_exposure      валовая экспозиция после сделки ≤ max_gross_exposure_pct
check_daily_loss          реализованный убыток за день < max_daily_loss_pct
check_order_count         ордеров за день < max_orders_per_day
check_session_window      время внутри разрешённой сессии
check_expiry              мандат не истёк
```

Тесты обязательны и они же — материал для ревью Qodo. Минимум по два случая на проверку: граница снизу и
граница сверху. Ордер ровно на лимите проходит, на цент выше — нет.

## 5. Схема мандата

`mandate.py`, pydantic. Тот же тип дублируется в `zod` для пульта.

```yaml
name: intraday-momentum-2026-08-28
universe: [AAPL, MSFT, NVDA, SPY]
instruments: [equity]
order_types: [limit]
session: regular_hours_only
limits:
  max_position_pct: 10
  max_gross_exposure_pct: 60
  max_daily_loss_pct: 2
  max_orders_per_day: 20
wake_me_if:
  - daily_loss_pct > 1.2
  - single_symbol_move_pct > 5
predecided:
  - when: daily_loss_pct >= 1
    then: park_new_orders
    reason: Protect the remaining daily loss budget before the hard stop.
allow_risk_reducing_market_close: true
expires: 2099-08-28T20:00:00Z
```

Правила валидации: `universe` непустой, все проценты в диапазоне 0–100,
`max_position_pct <= max_gross_exposure_pct`, `expires` в будущем. Невалидный мандат — сервер не стартует.

`wake_me_if` в первой версии — строки, разбираемые простым парсером из трёх токенов
`метрика оператор число`. Полноценный язык выражений не писать.

`predecided` использует тот же парсер, но принимает только метрики, доступные guard до исполнения
ордера (`daily_loss_pct`, `single_symbol_move_pct`). В M2 единственное действие — `park_new_orders`.
Сработавшая развилка добавляет breach и детерминированно запрещает новый ордер.

## 6. Компонент 2 — конфигурация агента

`agent/src/agentSpec.ts`, применяется через SDK. Точные имена полей взять из
`https://trueforge.dev/openapi.json`, ниже — смысл.

```
model: anthropic/<...>            # [УТОЧНИТЬ] точное имя из каталога моделей
instructions: prompt.md
mcp_servers:
  - name: mandate-guard
    enable_tools: ['@all']
    require_approval_for_tools:
      - submit_order_under_mandate
      - cancel_order
      - close_position
  - name: alpaca
    enable_tools: ['@read-only']    # только данные
    disable_tools:                  # [УТОЧНИТЬ] перечислить write-тулы поимённо
      - <все тулы размещения и изменения ордеров>
skills: [mandate-execution]
sandbox: enabled
subagents: enabled
generative_ui: enabled
```

**Почему поимённо, а не тегом.** TrueForge выводит `@write` и `@destructive` из MCP-аннотаций, а у Alpaca
аннотированы ровно три тула из 65 — остальные сгенерированы из OpenAPI и аннотаций не несут, значит под
дефолтную политику не попадают. Подробности в `.idea-research/FACTS.md`, раздел про `toolSelectors.ts`.

`[УТОЧНИТЬ]` Список тулов сервера Alpaca получить через эндпоинт «List tools of an MCP server» и выписать в
`agent/src/alpacaTools.ts` как явную константу с комментарием, какие read-only, какие write. Эта константа —
часть доказательной базы проекта, не служебный файл.

### Промпт

Короткий. Три вещи:
1. Ты работаешь внутри мандата. Прежде чем предлагать ордер, вызови `check_order`.
2. Если ордер не проходит — не спорь и не обходи. Либо перепланируй внутри лимитов, либо вызови `park`.
3. Все расчёты — кодом в песочнице, не в голове. Числа в ответе должны быть выводом кода.

Логику лимитов в промпт **не дублировать**. Она в guard'е. Промпт, повторяющий правила, создаёт иллюзию,
что модель их соблюдает.

## 7. Компонент 3 — анализ в песочнице

Агент пишет один скрипт в Code Mode. MCP-вызовы из песочницы бриджатся обратно в харнесс, креды внутрь не
попадают. Форма вызова:

```python
import asyncio
from mcp_client import call_tool

async def main():
    bars = await call_tool("alpaca", "<имя тула баров>", body={...})   # [УТОЧНИТЬ] имя
    ...
    print(summary)
```

Что скрипт делает: тянет бары по вселенной, считает индикаторы, считает размер позиции от текущего
капитала, вызывает `check_order` для кандидатов и печатает **короткую сводку**. Полные ответы API остаются
в песочнице и в контекст не попадают.

Подагенты: по одному на бумагу при анализе вселенной больше трёх символов. Наружу возвращается только
вердикт по бумаге, не сырые данные.

## 8. Компонент 4 — пульт

Собирается композицией `@truefoundry/trueforge-ui`, не с нуля. У них уже есть `ToolApprovalContainer` и
`ToolApprovalBar` — оборачиваем их, а не переписываем. `[УТОЧНИТЬ]` конкретные атомы и хуки смотреть в
`https://trueforge.dev/ui-sdk/reference/*`.

Четыре панели:

**MandatePanel.** Полоски «использовано / осталось» по каждому лимиту, данные из `get_mandate`.

**TimelinePanel.** Карточки событий сессии. Во время анализа — параллельные дорожки подагентов.
**Клик по любому числу раскрывает код из песочницы, который его посчитал, и его вывод.** Это ключевой
элемент интерфейса, не украшение: он одним движением доказывает, что песочница работает.

**DecisionCard.** Рендерится на `ToolApprovalRequiredEvent` для наших трёх write-тулов. Показывает не JSON,
а решение: что покупаем, каким ордером, какой пункт мандата пробит, портфель до и после, строка
«исполненный ордер необратим». Данные берутся из `breaches` и `portfolio_after`, которые вернул guard.
Две кнопки, отправляют `ApprovalAllow` / `ApprovalDeny`.

**PositionsPanel.** Позиции и P&L из `get_session_state`.

Поток событий — через подписку на выполняющийся turn. `[УТОЧНИТЬ]` точный эндпоинт и формат в
`https://trueforge.dev/ui-sdk/reference/events`.

## 9. Milestone'ы и приёмка

Каждый — отдельный PR с ревью Qodo. Milestone не закрыт, пока критерий не выполнен буквально.

**M0 — фундамент.**
Репозиторий, Qodo, защита main, `.env.example`, TrueForge запущен, сервер Alpaca подключён, бумажный счёт
живой.
*Приёмка:* агент в стоковом чате отвечает на «покажи мой баланс» настоящими числами со счёта.

**M0.5 — записать fail-open.**
Дефолтная политика, вызов write-тула из неаннотированного хвоста Alpaca.
*Приёмка:* видеозапись, на которой операция выполняется **без запроса подтверждения**. Это первые
пятнадцать секунд демо, снять до того, как всё закроем.

**M1 — guard без интерфейса.**
`mcp-guard` с полным набором тулов, схема мандата, проверки с тестами.
*Приёмка:* `pytest` зелёный; `check_order` на заведомо превышающем лимит ордере возвращает
`allowed=false` с непустым `breaches`.

**M2 — сквозной путь.**
Агент сконфигурирован, сырые write-тулы Alpaca отключены, guard подключён.
*Приёмка:* в стоковом чате TrueForge просим купить сверх лимита — агент упирается в отказ guard'а и
перепланирует. Просим в рамках лимита — появляется гейт, жмём allow, **ордер виден в интерфейсе Alpaca**.

**M3 — глубина.**
Code Mode, подагенты, `park`, вахтенный журнал.
*Приёмка:* журнал сессии выгружен из песочницы, лежит в `logs/`, содержит хотя бы одну запись
запаркованного действия.

**M4 — пульт.**
Четыре панели, карточка решения, раскрытие кода по клику на число.
*Приёмка:* весь сценарий из раздела 5 `SPEC.md` проходится в своём интерфейсе, ни разу не переключаясь в
стоковый.

**M5 — сдача.**
README, раздел `## Qodo Code Review Evidence`, видео.
*Приёмка:* чужой человек клонирует репозиторий, вставляет свои бумажные ключи и доходит до гейта.

### Точка невозврата
**Вечер пятницы 29 августа.** Если M4 не показывает карточку решения — режем пульт и показываем в стоковом
UI через OpenUI. M0–M3 без пульта уже составляют законченный проект.

## 11. Чего не делать

- Не писать свой бэктест-фреймворк. Достаточно расчёта индикаторов на барах.
- Не подключать опционы и крипту. `instruments: [equity]`.
- Не писать язык выражений для `wake_me_if`. Три токена.
- Не дублировать логику лимитов в промпте.
- Не строить систему тикетов, базу пользователей, авторизацию. Один локальный пользователь.
- Не делать копию чат-интерфейса. Стоковый уже есть и он лучше.
- Не оптимизировать доходность. Стратегия должна быть объяснимой за десять секунд, а не прибыльной.
- Не трогать историю коммитов ради красоты. Она — доказательство для Qodo.
